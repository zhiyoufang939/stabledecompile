## Context

参见 `proposal.md` 的动机以及三个 capability spec 的行为合同。当前实现已经有三套可运行的 WEIKU SeedType/Reanimation/Projectile 链路，但普通选卡把 C/B/A 当成三张卡；`Board::CanPlantAt` 和种植提交路径只认识原版紫卡式升级关系。主界面和图鉴使用传统 Widget/Dialog，逻辑画布为 800×600。

玩家档案目前由 `PlayerInfo::SyncDetails` 按版本 12 顺序序列化；版本不相等会提前返回。当前测试逻辑还会在读档后把 `mCoins` 强制写为内部值 1,000,000，而界面按 10 倍显示；`AddCoins` 的旧上限 99,999 又与这一初始值冲突。若不先修正，500,000 显示金币的改装扣款无法可靠持久化。

高分辨率 WEIKU PNG 会带来显著纹理内存开销，因此车库不应为了预览同时创建 C/B/A 的完整动画实例。当前构建是非宽字符版本，车库文字必须继续走字符串资源和安全的 ASCII 回退。

## Goals / Non-Goals

**Goals:**

- 建立一个由稳定车辆 ID 和稳定等级 ID 驱动的注册表，统一服务于车库、档案进度和战斗叠种解析。
- 让“永久解锁上限”和“单局场上等级”成为两个明确分离的状态。
- 在保留现有 C/B/A 战斗资源和旧枚举值的前提下，把普通玩家入口收敛到一张威酷卡。
- 对旧版本用户档案和已有战斗存档提供明确、可测试的迁移路径。

**Non-Goals:**

- 本 change 不制作中文字体链、3D 车辆模型、旋转镜头或复杂赛车特效。
- 本 change 不实现尚无素材和战斗定义的威酷S，只保证追加 S 时不需要改车库/叠种状态机。
- 本 change 不把植物图鉴改造成车库，也不把其他原版植物纳入车辆升级体系。
- 本 change 不重做特殊模式、传送带或迷你游戏的卡牌投放规则；首期保证普通选卡与正常关卡流程。

## Decisions

### 1. 使用稳定 ID 的车辆/等级注册表

新增独立的车辆定义模块（建议 `Lawn/Vehicle/VehicleDefs.h/.cpp`），核心概念为：

- `VehicleId`：稳定标识车辆家族，例如 `VEHICLE_WEIKU`。
- `VehicleTierId`：稳定标识具体等级，例如 `WEIKU_C/B/A`；持久化该 ID，而不是可变的数组下标或字母序号。
- `VehicleDefinition`：名称、简介、家族卡 SeedType、默认等级、按展示顺序排列的 tier 列表。
- `VehicleTierDefinition`：等级标签、对应战斗 SeedType/ProjectileType、预览图片 ID、属性文本键、升级到本级的显示金币费用，以及用于数值条的展示范围/权重。

注册表提供按车辆查 tier、按 SeedType 反查 tier、取前后级、判断最高级、读取玩家最高解锁级等无副作用查询。添加 S 仍需追加新的 SeedType/Projectile/资源注册，这是游戏实体的必要工作；但车库布局、购买流程和 Board 叠种分支只读取新定义行，不增加 `if (tier == S)`。

备选方案是继续在车库、选卡和 Board 中分别判断 C/B/A。该方案短期改动少，但加入 S 或第二辆车时会复制状态机并造成显示数据与战斗数据漂移，因此不采用。

### 2. 战斗数值保持单一来源，注册表保存映射和展示元数据

现有 `gPlantDefs`、`gProjectileDefinition` 和 A/B/C 配置头继续作为真实阳光、冷却、伤害、动画时间的来源。车辆注册表保存 SeedType/ProjectileType 映射，并通过公共查询读取真实战斗值；属性文案、预览图、条形范围和升级费用属于车库数据，保存在 tier 定义中。

这样不会在 UI 再复制一份“伤害 20/40/60”后忘记同步。威酷家族卡使用 `SEED_WEIKU_C` 作为稳定卡牌身份，其费用调整为 100；B/A 的定义继续存在以创建和恢复场上实体，但不再进入普通 chooser。

### 3. 玩家进度使用可扩展的尾部记录并迁移版本 12

`PlayerInfo` 增加有界的车辆进度记录集合，每条包含稳定 `VehicleId` 与最高 `VehicleTierId`。序列化尾部写入“记录格式版本 + 条目数 + ID 对”，未出现的已登记车辆回退到定义的默认等级。这样以后增加车辆时无需改变旧条目的位置，移除未发布车辆时也能跳过未知 ID。

用户档案版本提升到 13，但读取端显式支持版本 12 和 13：

- 版本 12 按原布局读取到结尾，不读取车辆尾部，然后初始化威酷=C。
- 版本 13 读取车辆尾部，校验条目数、车辆 ID 和 tier 是否属于该车辆；无效值回退到默认级，不越界。
- 更早或未知版本继续走现有失败策略，避免猜测不同布局。

第一次把有效 v12 档案保存为 v13 前，保留一次 `.pre-garage-v12` 备份，供构建回滚时人工恢复。`DeleteUserFiles` 同步清理对应备份/扩展文件规则，避免删除档案后残留进度。

备选方案是复用 `mPurchases` 空槽或仅保存 tier 数组下标。前者会与商店项目耦合且容量语义不稳定，后者在插入/删除等级后会指向错误等级，均不采用。

### 4. 统一金币单位并让余额真正持久化

对外的升级费用始终以界面金币表示：500,000。交易层用唯一换算函数转换为内部值 50,000（当前界面倍率为 10），并要求费用可整除该倍率。交易函数在一次调用中重新验证下一级、余额和当前进度，验证全部通过后才同时扣款并提升 tier，随后调用 `SaveDetails`。

删除 `SyncDetails` 读取成功后强制设置 `mCoins = 1000000` 的逻辑，只在 `Reset()`/新档案中保留这一初始值。将金币上限集中为至少内部 1,000,000（显示 10,000,000），修正 `AddCoins` 不能把现有高余额意外截断为 99,999 的冲突。车库显示余额继续复用现有 `GetMoneyString`。

改装按钮点击后先弹确认框；确认回调再次执行交易验证，并在处理期间禁用按钮，防止双击重复扣款。保存接口当前不返回失败状态，因此首期原子性保证到“内存中的扣款和解锁同时发生”；磁盘写入异常沿用现有档案保存错误处理，不在本 change 引入事务文件系统。

### 5. 新建独立 GarageDialog，不扩展 AlmanacDialog 页面

新增 `DIALOG_GARAGE`、`GarageDialog` 及 `LawnApp::DoGarageDialog/KillGarageDialog`，并在 `GameSelector` 增加独立车库按钮。这样车库的购买状态、车辆选择和未来多车分页不会污染图鉴的植物/僵尸页状态。

车库按 800×600 逻辑区域绘制：

| 区域 | 内容 |
|---|---|
| 左上 | 大号等级标识、车辆名、该 tier 的属性标签 |
| 中央 | 当前最高解锁 tier 的车辆预览与简洁车库舞台背景 |
| 左下 | 阳光、伤害、冷却的文本值和数据驱动条形图 |
| 右侧 | 按定义顺序排列的 C→B→A→未来等级缩略图路径 |
| 下方 | 可爱简介；威酷首期文案语义为“威威又酷酷” |
| 右下 | 下一等级/费用和“赛车改装”按钮，或余额不足/已满级状态 |

中央预览和路径缩略图优先直接绘制当前 tier 的单张预览图（可先复用各自 `idle_00`），不同时创建三套完整 Reanimation；后续可替换为专用降采样车库图而不改变接口。背景、面板和条形可先用项目现有 Image/Graphics 基元完成，最终美术资源是可替换层。

所有文本通过 `LawnStrings.txt` 键读取。首期资源同时提供 ASCII 安全文案（如 `GARAGE`、`WEIKU - C CLASS`、`Cute and cool!`）；若后续接入中文字形，只替换本地化文本，不改 UI 逻辑。

### 6. 用一个纯解析器驱动可种植判断和实际提交

新增无副作用的放置解析函数，输入“家族卡 SeedType、目标格普通植物 SeedType、玩家最高解锁 tier”，输出：

- 空位创建默认 C；
- C→B、B→A（或未来 A→S）的具体下一 SeedType；
- `LOCKED_NEXT_TIER`、`ALREADY_MAX_TIER`、`INVALID_TARGET` 等拒绝原因。

`Board::CanPlantAt`、光标高亮/提示和 `MouseDownWithPlant` 的实际替换必须调用同一个解析器，避免预览允许但提交失败，或提交绕过车库门槛。威酷家族卡不加入 `Plant::IsUpgrade`：它既能种空位又能升级同家族，和只能覆盖前置植物的原版紫卡语义不同。

成功升级时，先完成现有地形/格子校验，再扣 100 阳光、销毁同格普通威酷实体并用解析得到的下一 SeedType 创建新实体；底层睡莲/花盆和外层南瓜保持。种子栏只对家族卡执行一次 `WasPlanted()`，因此种植与每次升级都使用相同冷却。任何锁定、满级或非法目标结果都在扣阳光和触发冷却之前返回。

备选方案是临时把 C 卡改写为 B/A 卡再走 `Plant::IsUpgrade`。这会污染种子包身份、工具提示和存档，并会让空位种植与紫卡限制互相冲突，因此不采用。

### 7. 兼容旧 SeedType 与旧战斗存档

`SEED_WEIKU_C/B/A`、对应 ProjectileType 和 ReanimationType 不删除、不重排。新 chooser 仅列出 C 作为家族卡，但旧存档恢复出的场上 B/A 仍按原定义运行，也不会因为当前车库只解锁 C 而被降级。

旧战斗存档若在 SeedBank 中保存了独立 B/A 卡，加载后的规范化步骤把 packet type/imitater type 映射为家族卡 C，并保留可合理映射的刷新进度；场上实体不参与该规范化。这样恢复后不会继续绕过车库解锁规则直接种 B/A。

## Risks / Trade-offs

- [用户档案版本迁移错误可能触发 Reset 并丢失进度] → 使用真实 v12 fixture 做迁移测试、在首次 v13 写入前留备份、对条目数和 ID 做边界校验。
- [显示金币与内部金币相差 10 倍，容易扣错或被旧上限截断] → 费用常量使用显示单位、只经统一换算/交易函数扣款，并覆盖 499,990/500,000/500,010 等边界测试。
- [主界面原布局没有预留车库按钮] → 车库入口使用独立资源和命中区域，验证 800×600 与宽屏偏移；不覆盖商店、图鉴或禅境花园按钮。
- [高分辨率预览同时加载会进一步放大内存] → 首期一次只绘制当前 tier 单帧，路径使用缩略绘制；后续允许替换成专用降采样图。
- [放置判断分散导致免费升级或误扣阳光] → 所有判断和提交共用解析器，并在扣费后不再做会改变结果的第二套分支。
- [旧战斗存档含独立 B/A seed packet] → 加载时只规范化 seed packet，明确不改场上实体，分别做回归验证。
- [未来增加 S 仍需要注册资源和枚举] → 保持枚举追加原则；将新增工作限制为实体/资源注册和一行 tier 定义，不修改车库或升级状态机。

## Migration Plan

1. 先引入车辆注册表和纯查询/解析测试，不改变 chooser 行为。
2. 加入 PlayerInfo v13 读写、v12 迁移备份和金币持久化修复，用旧档案副本验证金币及其他字段保持。
3. 接入 GarageDialog、主界面入口、字符串与预览资源，验证 C→B→A 两次 500,000 交易和重启持久化。
4. 将 chooser 收敛为 C 家族卡，再接入空位 C、同格 B/A 解析和旧 seed packet 规范化。
5. 按项目固定链路运行资源同步、`DebugGOTY|x64` 构建、启动，并人工检查主界面、车库、金币、选卡、叠种、各级攻击与旧存档。

若需要回滚构建，代码和资源回到前一版本，并将首次迁移保存的 `.pre-garage-v12` 文件恢复为对应用户档案；因为旧程序不认识 v13，不直接让它读取已升级的档案。

## Open Questions

- 最终车库背景、按钮皮肤和数值条配色尚无仓库内正式素材；首期使用参考图的区域关系和现有绘制基元，后续美术替换不改变规格或任务拆分。
- 中文字体链不属于本 change；在其完成前使用 ASCII 回退，完成后只需替换字符串资源。
